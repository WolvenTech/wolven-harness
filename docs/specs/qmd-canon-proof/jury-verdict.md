# QMD canon proof — advisory Jury verdict

## Frame

- **Question:** What is the smallest credible way to establish that the harness searches and applies current canon through QMD?
- **Options:** A — prose/static contracts alone; B — bounded authentic behavioral evidence, independent controls and targeted amendments; C — mandatory hooks and multiple runtimes now.
- **Evidence:** Original `jury-input-spec.md`, draft decision and deferral, existing QMD instructions, static contract tests, validator/consumer setup contracts. No live QMD proof exists; executor is unverified.

## First-round opinions (independent)

Five separate agents were launched in the same turn with isolated contexts, the shared frame and their own named juror role. All full opinions were recorded before any shared deliberation. See `jury-round1-record.md` and individual `jury-round1-{proponent,skeptic,integrator,risk,evidence}.md` files; none were overwritten.

All five selected B. Proponent confidence: high on choice, medium on coverage. Skeptic: medium. Integrator: medium. Risk: high on B, medium on unamended current-canon proof. Evidence: medium. These are advisory judgments about the design, not independent empirical evidence of QMD reliability.

## Deliberation notes

Each same juror then received the full independent record. Full responses are preserved in `jury-round2-{proponent,skeptic,integrator,risk,evidence}.md`.

- **Agreement:** All held B; all required minimum freshness coverage and authoritative source comparison. Static text cannot prove execution; required calls alone cannot prove applicable authority. Authentic complete capture and oracle isolation remain prerequisites.
- **Disagreement:** No option-level minority. Risk initially emphasized authorized refresh; the other seats emphasized read-only stale blocking as well. Both survive in C2. Cost reduction (no candidate if baseline passes) and held-out confirmation (when changed) both survive. Confidence varies because executor feasibility and live behavior remain untested.
- **Revisions:** No seat changed choice. Shared arguments added action-boundary capture, held-out confirmation, conditional campaign, explicit escalation and bounded inference. First-round records remain intact.
- **Resolution:** Incorporate minimum stale-index probe; independent source hashes/range comparison; all visible conclusions/tools/writes; qualification before substantial runner work; no failed-seed replacement; explicit critical-invariant gate. Round 2's count correction yields nine scored variants: 90 baseline, and only if changed, 90 paired plus 90 held-out candidate runs (270 maximum before additional diagnosis attempts). Source snapshot/range normalization and how read-only agents diagnose staleness are specified. No universal enforcement claim is made.

## Verdict (advisory — Human decides)

- **Decision:** B, as amended. Qualify one real executor before committing to the live integration. Block evidence claims if it cannot supply complete authentic observations.
- **Rationale:** This tests the principal upside with the smallest scope that rejects the dangerous false greens, while preserving existing public contracts. Freshness is part of correctness, not an optional benchmark extension.
- **Dissent:** None on option — unanimous. Preserve the qualifications from Risk (capture and stale-source blast radius), Evidence (no private-causation or universal-reliability proof), Skeptic (overfit/false green), Integrator (executor feasibility and campaign cost), Proponent (do not amend a passing baseline gratuitously).
- **Confidence:** Medium overall — strong agreement on method; no qualified executor or live campaign evidence yet.
- **Concrete test:** On one qualified executor, index an initial decision, replace its applicable source value while leaving the index stale, then run a read-only natural goal. Authentic trace must show ADR search and retrieval followed by source mismatch diagnosis and explicit blocking; the scorer must reject a deliberately constructed stale-value answer carrying otherwise valid receipts. Failure of either condition overturns acceptance of the proposed gate.
- **Authority:** Advisory only. Human retains approval of draft spec/decision. Requested spec amendments were applied; no runner, hooks, service changes, plan, commit or PR was executed.
