# Expand QMD evaluation only after canon proof

Current need is actual canon retrieval and use, not general search performance. One executor, six cases, authentic receipts and independent negative controls answer that first. See the qmd-canon-proof draft spec.

## Deferred scope and triggers

- [ ] Revisit mandatory completion hooks when a ready, calibrated campaign still observes any critical canon-use bypass after one targeted instruction amendment, or a real consumer incident requires prevention rather than detection.
- [ ] Revisit a second runtime/transport adapter when a named consumer must run the same canon gate on that runtime and provides authentic trace access.
- [ ] Revisit load/concurrency sweeps when the correctness campaign passes and measured latency/resource failures violate a named service budget at its observed corpus size or concurrency.
- [ ] Revisit broad freshness matrices, archive/filter and retrieved-instruction adversarial cases when the six core cases pass or a consumer supplies an actual incident in one of those categories. The minimal stale-index/current-bytes transition is in the core C2 gate, not deferred. Data integrity/security incidents are not blocked by YAGNI.

No deferred feature is implemented or implicitly approved.
